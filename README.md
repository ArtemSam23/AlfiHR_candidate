# Код ревью агента AlfiHR

AlfiHR — корпоративный поиск и чат. Он отвечает на вопросы по внутренним документам и вызывает банковские сервисы. Модель доступна через API; её обучение и развёртывание делает другая команда.

Перед вами упрощённая обвязка такого агента. Она хранит диалог, обращается к модели, выполняет инструменты и позволяет продолжить или повторить запуск.

## Как должно работать

- Агент учитывает важные ограничения пользователя на протяжении диалога. Например, просьба «пока только найди информацию, заявку не создавай» продолжает действовать до явного изменения указания.
- Повторная обработка одной команды создания заявки не должна создавать дубликаты, в том числе при повторной доставке, таймауте и восстановлении после сбоя. Отменённая или некорректная команда может не создавать заявку вообще.
- Повторный прогон для отладки позволяет разобрать прежний запуск и не создаёт новые заявки во внешней системе.
- Неправильный ответ модели или сбой интеграции не должен приводить к неконтролируемому выполнению или бесконечному ожиданию.
- Пользователь может отменить задачу или изменить её, пока она выполняется. Например, агент готовит отпуск с 1 по 5 декабря, а пользователь пишет: «Передумал, пока ничего не оформляй». Устаревшая работа не должна запускать новые действия или выдавать результат как актуальный. Уже выполненное действие автоматически не откатывается.

## Контракты

`model.next(messages, tools)` — внешний LLM API через адаптер. Адаптер скрывает особенности протокола провайдера. Нормальный результат имеет один из двух видов:

```python
{"kind": "tool", "name": "search", "args": {"query": "правила отпуска"}}
{"kind": "final", "text": "Ответ сотруднику"}
```

Модель может вернуть неизвестный инструмент, некорректные аргументы, повторять один вызов или не ответить. История здесь — внутренний формат приложения, а не формат OpenAI API.

`tools` — словарь асинхронных функций:

- `search(query: str)` читает корпоративные документы и возвращает список результатов с текстом и источником. Ответ может быть большим.
- `vacation(start: str, end: str)` создаёт заявку на отпуск текущего сотрудника и возвращает объект с `id`, `start`, `end`. Даты — ISO `YYYY-MM-DD`. API может успеть создать заявку, а затем не доставить ответ. Текущий контракт не принимает ключ идемпотентности и не предоставляет поиск операции по такому ключу.

`store.load(chat_id)` и `store.save(chat_id, messages)` — чтение и атомарная запись снимка диалога во внешнее постоянное хранилище. Сервис агента может завершиться между любыми двумя операциями. Хранилище и HR API не участвуют в общей транзакции. В локальном примере хранилище заменено на `MemoryStore`; его устройство обсуждать не требуется.

Аутентификация выполнена внешним слоем, инструменты уже ограничены текущим сотрудником. Авторизацию, поисковый индекс, качество самой модели и развёртывание инфраструктуры в этом задании не рассматриваем. Можно предлагать изменения контрактов интеграций.

## Необязательный запуск

Нужен Python 3.12 или новее. Зависимостей и API-ключей нет.

```bash
python demo.py
```

`integrations.py` содержит прозрачные локальные заглушки. `ScriptedModel` возвращает подготовленные ответы и не имитирует понимание языка. На собеседовании обсуждаем прежде всего `agent.py`.
